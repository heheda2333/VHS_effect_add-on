# VHS Effect Add-on · 录像带效果处理工具

[English](README.en.md) | 简体中文

为照片与视频叠加 VHS 录像带效果。程序模拟色度串色、时基误差、磁头切换噪声、追踪失真、掉磁、噪点、扫描线与暗角等特征，并可在画面上叠加录像机风格的屏显文字（REC 指示、播放状态、日期时间）。工具递归处理整个目录树，在输出目录中重建与输入同名的文件夹结构，同时提供图形界面与命令行两种入口，仅依赖 NumPy、Pillow 与 OpenCV，视频编解码由 ffmpeg 完成。

- 待处理的照片与视频置于 `input` 目录
- 处理结果写入 `output` 目录
- `input` 目录仅作读取：本工具不修改、不移动、不删除任何原始文件
- 效果示例见 `example` 目录：`before.jpg` 为原图，`after.jpg` 为处理结果

---

## 一、目录规则

工具自动识别 `input` 目录中的子文件夹，并在 `output` 目录中生成同名文件夹：

| 输入目录中的内容 | 输出结果的位置 |
| --- | --- |
| `input/照片.jpg`（文件置于根目录） | `output/照片.jpg` |
| `input/A/`（整个文件夹放入） | `output/A/` 中的同名结果 |
| `input/A/B/`（多层嵌套） | `output/A/B/`，目录结构完整镜像 |
| 文件与文件夹混合放置 | 分别归入对应位置，互不影响 |

```
input/                        output/
├─ 照片.jpg          -->      ├─ 照片.jpg
├─ A/                          ├─ A/
│  ├─ 01.jpg         -->      │  ├─ 01.jpg
│  └─ 02.mp4         -->      │  └─ 02.mp4
└─ A/B/                        └─ A/B/
   └─ 03.jpg         -->         └─ 03.jpg
```

- 输出文件名默认与输入相同，便于对照；如目标文件已存在，将自动追加 `_vhs`、`_vhs2` 等后缀，不会覆盖已有结果
- 如需输出名始终附加 `_vhs` 后缀，可加参数 `--suffix`，或在图形界面中勾选对应选项
- 输入目录中的非图片、非视频文件（如 txt）将被忽略，不影响目录结构
- 输出目录不得位于输入目录之内，程序会拒绝此类配置以避免重复扫描
- 也可通过参数指定其他目录，完全不涉及 `input` 与 `output`：

```bat
python vhs_processor.py run -i <输入目录> -o <输出目录>
```

## 二、使用方式

### 1. 图形界面（推荐）

运行 **`运行-图形界面.bat`**，在窗口中选定目录并调节参数后点击"开始处理"。

界面分为五个页签：

| 页签 | 内容 |
| --- | --- |
| 效果强度 | 预设选择、整体强度倍率，以及色度串色、噪点、扫描线、抖动、柔化、泛光、饱和度等 19 项参数滑块 |
| 输出设置 | 图片最长边与 JPEG 质量、视频输出高度与质量参数、编码器与速度预设、音轨保留、处理范围 |
| 日期时间叠加 | 起始日期时间的输入与实时校验、推演方式、时间流逝倍率 |
| 叠加文字 | REC / PLAY / 日期时间三个元素的开关、REC 圆点颜色与闪烁频率、文字大小与不透明度 |
| 处理日志 | 逐文件的处理结果、进度条与状态提示 |

- 各页签中的滑块均显示当前数值，并附带该参数的简短说明
- 修改预设后点击"按预设重置各项参数"，可将全部滑块恢复为该预设的取值
- "预览单张"按钮仅处理输入目录中的第一张图片，便于快速确认效果
- 处理在后台线程中进行，界面不会失去响应；点击"中止"可在当前文件处理完成后停止
- 处理结束后列出结果所在的全部文件夹，并询问是否立即打开输出目录
- 各项设置自动保存至 `_gui_settings.json`，下次启动时沿用

### 2. 命令行批处理

运行 **`运行-命令行.bat`**：将 `input` 目录中的照片与视频（含各子文件夹）
处理后写入 `output` 目录中的对应文件夹。

### 3. 命令行（可附加参数）

```bat
python vhs_processor.py                          :: 处理 input 目录，结果写入 output 目录
python vhs_processor.py --preset heavy           :: 使用重度预设
python vhs_processor.py --strength 1.5           :: 在预设基础上整体加强
python vhs_processor.py --time "2001-09-11 08:46:00"   :: 指定右下角日期时间
python vhs_processor.py --encoder cpu            :: 强制使用 CPU 编码
python vhs_processor.py --no-osd                 :: 不叠加任何屏显文字
python vhs_processor.py presets                  :: 列出全部预设
python vhs_processor.py show --preset heavy      :: 打印当前生效的全部参数
```

处理期间可随时按 **Ctrl+C** 中止：程序不保存进度，已完成的文件保留在输出目录，
正在处理的半成品文件会被删除。

## 三、命令行参数

| 参数 | 说明 |
| --- | --- |
| `-i, --input` | 输入目录，默认为本工具目录下的 `input` |
| `-o, --output` | 输出目录，默认为本工具目录下的 `output` |
| `--preset, -p` | 预设：`light` / `classic` / `heavy` / `worn` / `clean_tv`，默认 `classic` |
| `--strength, -s` | 整体强度倍率：`1.0` 为预设原样，`0.5` 减半，`2.0` 加倍 |
| `--set 键=值` | 单项参数覆盖，可重复使用，例如 `--set luma_noise=1.2` |
| `--time, -t` | 起始日期时间，自动识别多种写法（见第五节） |
| `--time-offset` | 在起始时间基础上平移若干秒，例如 `--time-offset -3600` |
| `--timestamp-mode` | `auto`（默认，照片固定、视频递增）/ `fixed` / `advance` |
| `--timestamp-speed` | 时间流逝倍率，`2.0` 表示视频内时间流逝速度加倍 |
| `--timestamp-text` | 直接指定时间戳文字，指定后不再进行时间推演 |
| `--rec-color` | REC 圆点颜色，形如 `#FF2E2E` 或 `255,46,46` |
| `--rec-blink` | REC 圆点闪烁频率（赫兹），`0` 表示常亮 |
| `--no-osd` / `--osd` | 关闭 / 强制开启全部叠加文字 |
| `--no-timestamp` | 仅关闭右下角日期时间 |
| `--height` | 视频输出最大高度，默认 `1080` |
| `--crf` | 视频质量参数，数值越小质量越高，默认 `18` |
| `--encode-preset` | 编码速度预设，默认 `medium` |
| `--encoder, -e` | 编码器：`auto` / `cpu` / `gpu` / `nvenc` / `qsv` / `amf` |
| `--no-audio` | 丢弃音轨 |
| `--video-ext` | 强制输出扩展名，例如 `.mp4` |
| `--video-seconds` | 每个视频仅处理前若干秒，便于快速预览 |
| `--no-image` / `--no-video` | 仅处理视频 / 仅处理图片 |
| `--suffix` | 输出文件名追加 `_vhs` 后缀 |
| `--quality` | JPEG 输出质量，取值 1-100，默认 `95` |
| `--seed` | 随机种子；相同种子结果完全一致 |
| `--traceback` | 出错时打印完整调用栈 |

单文件处理：

```bat
python vhs_processor.py image "input/照片.jpg" -o "output/照片.jpg"
python vhs_processor.py video "input/影片.mp4" -o "output/影片.mp4"
```

## 四、预设

| 预设 | 效果 |
| --- | --- |
| `light` | 轻微。画质损失很小，仅带一点录像带质感 |
| `classic` | 经典。默认取值，各方面表现均衡 |
| `heavy` | 重度。噪点、抖动与串色均较明显 |
| `worn` | 破损。模拟经多次翻录、磨损严重的录像带 |
| `clean_tv` | 电视。干净的录像带在老式显像管电视上播放的效果 |

参数的优先级由低到高为：预设 → 配置文件 → 命令行选项。
配置文件 `vhs_config.json` 可指定默认预设、整体强度与任意参数覆盖：

```jsonc
{
  "preset": "classic",
  "strength": 1.2,
  "params": {
    "luma_noise": 1.0,      // 噪点更强
    "jitter": 0.9,          // 抖动更明显
    "osd_rec_blink": 2.0    // REC 圆点闪烁更快
  }
}
```

## 五、日期时间叠加

程序会自动识别输入的时间写法，无需记忆固定格式。

- **照片**：直接印制起始时间，画面上的时间保持固定。
- **视频**：自起始时间开始按秒递增（第 1 秒为 08:46:01，第 2 秒为 08:46:02……）。
- 时间戳**每秒跳变一次**，与真实录像机的屏显行为一致，而非逐帧变化。

### 可识别的写法

| 输入 | 解析结果 |
| --- | --- |
| `1994-06-11 12:00:00` | 完整的日期与时间 |
| `1994/6/11 12:00` | 斜杠分隔，省略秒 |
| `1994-06-11`、`19940611` | 仅日期，时间取默认值 12:00:00 |
| `12:00:00`、`12:00`、`120000` | 仅时间，日期取默认值 1994-06-11 |
| `1994年6月11日 12点00分00秒` | 中文写法 |
| `1994年6月11日12时30分` | 中文写法，省略秒 |
| `19940611120000` | 14 位纯数字 |
| `now`、`现在`、`今天` | 当前系统时间 |

未指定的部分沿用默认值（`1994-06-11 12:00:00`）。无法识别时将明确报错并列出
全部支持的写法，退出码为 2，不会使用错误的时间继续处理。

### 常用调整

```bat
:: 前后平移（单位：秒）
python vhs_processor.py --time "12:00:00" --time-offset -3600
python vhs_processor.py --time "2001-09-11" --time-offset 28800

:: 时间流逝加速
python vhs_processor.py --time "12:00:00" --timestamp-speed 4.0

:: 视频也固定显示同一时间
python vhs_processor.py --timestamp-mode fixed --time "12:00:00"

:: 完全指定文字，不进行时间推演
python vhs_processor.py --timestamp-text "1994-06-11  12:00:00"
```

### 屏显元素

| 元素 | 位置 | 说明 |
| --- | --- | --- |
| REC 指示 | 左上角 | 红色圆点与文字。照片中保持常亮；视频中按设定频率闪烁 |
| 播放状态 | 右上角 | 播放三角图标与 `PLAY`、`SP` 字样 |
| 日期时间 | 右下角 | 按上述规则推演 |

播放三角采用多边形绘制，不依赖字体是否包含对应字形，因此在任何系统上均可正常显示。
圆点颜色与闪烁频率均可调整；文字大小、不透明度、抖动幅度与色差重影强度亦可调整，
其中色差重影过强时红色标记会偏向紫色，默认取值已作平衡。

## 六、视频与编码

- 音轨默认原样保留：先抽取为 AAC，处理完成后合并回视频
- 输出统一为 H.264 与 `yuv420p`，兼容常见播放器与剪辑软件
- 逐帧处理为 CPU 密集运算，**降低输出分辨率是最有效的提速手段**
- 处理期间可随时中止，半成品文件会被自动清理

### 硬件编码说明

程序支持将编码环节交给硬件编码器（NVIDIA NVENC / Intel Quick Sync / AMD AMF），
通过 `--encoder` 选择，默认为 `auto`（优先硬件，不可用时回退 CPU）。

**需注意：硬件编码对总耗时几乎没有影响。** 视频处理的耗时集中在逐帧像素运算上，
编码只占其中很小一部分。以 1920×1080 为例，编码器本身的速度可达每秒上百帧，
而叠加效果后的整体速度约为每秒一帧量级，因此把编码从 CPU 移到硬件编码器，
端到端耗时的差异通常在百分之几。

硬件编码的实际价值在于**降低编码阶段的 CPU 占用与功耗**，而非缩短总耗时。
若需显著提速，应降低输出分辨率（`--height`）。

## 七、常见问题

**问：处理速度很慢。**
答：逐帧像素运算本身较为耗时，属正常现象。可采取以下措施：使用 `--height 720`
降低视频输出分辨率；用 `--video-seconds 5` 先处理片段确认效果；
适当降低 `luma_noise` 与 `chroma_noise`；图片处理速度远快于视频，
单张 5120×2880 的图片约需数秒。

**问：换用硬件编码后速度没有提升。**
答：属预期行为。瓶颈在像素运算而非编码，详见第六节。

**问：REC 圆点颜色不是红色。**
答：可通过 `--rec-color` 指定颜色，形如 `#FF2E2E`。另需注意，
"色差重影"（`--set osd_ghost=...`）数值过大时，红色标记会偏向紫色。

**问：视频中的 REC 圆点没有闪烁。**
答：闪烁仅在视频处理时启用，照片始终显示常亮的圆点（单帧画面中闪烁无意义）。
闪烁频率由 `--rec-blink` 控制，设为 `0` 表示常亮。

**问：右上角的播放三角显示为方框。**
答：该图标由程序绘制，不依赖系统字体，正常情况不会出现此问题。
若出现，请确认使用的是当前版本。

**问：输出文件名与输入不同，或多了后缀。**
答：默认沿用输入文件名。当目标文件已存在时，程序会自动追加 `_vhs` 等后缀以避免
覆盖；如希望始终附加后缀，请使用 `--suffix`。

**问：是否可以重复处理，是否会覆盖已有结果。**
答：可以。程序不会覆盖任何已存在的输出文件，冲突时会自动改名。

**问：是否会影响原始文件。**
答：不会。程序仅读取输入目录、仅写入输出目录，代码中不含任何删除或移动原始文件的操作。

**问：输出视频没有声音。**
答：说明音轨处理失败（源文件音轨编码特殊，或 ffmpeg 不可用）。程序会自动退化为
无音轨输出而非中断处理，运行 `python check_env.py` 可查看视频链路状态。

**问：能否处理带透明通道的图片。**
答：透明区域会合成到黑色背景后参与处理，输出为不透明的 JPEG。

**问：如何获得完全一致的可重复结果。**
答：固定 `--seed` 即可（默认为固定值）。视频的时间相关失真由帧序号驱动，
因此同一视频每次处理结果相同。

## 八、自检

```bat
python selftest.py
python selftest.py --keep          :: 保留测试产物以便查看
python selftest.py --source <素材目录>
```

自检分六个部分，逐项检查并输出结论：

1. **运行环境** —— Python 版本、各依赖库、ffmpeg 与硬件编码器可用性
2. **日期时间解析与推演** —— 10 种时间写法的解析结果、非法输入的拒绝、
   照片时间固定、视频时间逐秒递增、REC 圆点常亮与闪烁、圆点颜色
3. **参数装配** —— 单项参数覆盖、整体强度缩放、预设之间的差异、非法参数报错
4. **文件夹镜像** —— 递归扫描、非媒体文件跳过、含中文名与多层嵌套的输出结构
5. **图片处理** —— 对素材目录中的全部图片执行完整处理
6. **视频处理** —— 对素材目录中的全部视频处理前若干秒，含音轨合并

自检不会修改 `input` 与 `output` 目录，全部产物写入 `_selftest`
并在结束时清理（加 `--keep` 可保留）。

## 十、处理流程

画面处理按以下顺序进行，顺序本身影响最终观感：

1. **色度通道劣化** —— 转换至 YCbCr，对色度做各向异性低通、降采样与红蓝错位，
   模拟 VHS 色度带宽不足造成的横向拖尾与色边
2. **时基误差** —— 整幅抖动、逐行独立抖动与垂直滚动
3. **光学处理** —— 柔化、高光泛光、边缘增强、对比度与饱和度调整
4. **磁头切换** —— 画面底部的噪声带，含横向撕裂与亮度错位
5. **追踪失真** —— 缓慢上移的失真区域
6. **掉磁** —— 随机出现的亮线或暗线
7. **噪点** —— 细颗粒、低频块状颗粒、彩色噪点与脏边
8. **扫描线与暗角**
9. **屏显文字** —— REC、播放状态与日期时间
10. **软限幅** —— 模拟复合视频过冲后压回合法范围

运算全程使用 `float32`，值域为 `[0, 1]`，避免 uint8 反复截断产生色带。

### 性能

单核 CPU 上的参考值（`classic` 预设，已安装 OpenCV）：

| 分辨率 | 处理速度 |
| --- | --- |
| 640×360 | 约 7 帧/秒 |
| 854×480 | 约 4.8 帧/秒 |
| 1280×720 | 约 1.9 帧/秒 |
| 1920×1080 | 约 1.2 帧/秒 |

程序内部已采取的优化措施：噪声纹理池化复用并按四分之一分辨率生成；
泛光在半分辨率上计算；模糊、暗角与屏显字形全部缓存；
屏显文字仅混合字形所在的小矩形，不触碰整幅画面；
颜色调整采用原地运算并复用亮度缓冲；逐行偏移通过一次重采样完成，
不使用逐行循环。

## 十一、作为库调用

```python
from vhs_lib import resolve_preset, parse_start_time, VHSContext

params = resolve_preset("heavy")
ctx = VHSContext(
    params,
    (1080, 1920),                            # (高, 宽)
    fps=25.0,
    start_time=parse_start_time("2001-09-11 08:46:00"),
    advancing=True,                          # 视频为 True；照片为 False 则时间固定
)
out_frame = ctx.process(frame, frame_index=0)   # 输入输出均为 BGR uint8
```

`VHSContext` 绑定一组参数与一个分辨率，同一分辨率下可反复送入帧，
静态图层只计算一次。

批量处理可复用 `vhs_lib.vhs_task`：

```python
from vhs_lib.vhs_task import scan_tree, mirror_out_path, do_image

images, videos, skipped = scan_tree("input")
for src in images:
    dst = mirror_out_path(src, "input", "output")
    do_image(src, dst, params, quality=95)
```
